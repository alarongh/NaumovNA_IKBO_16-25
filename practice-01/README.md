# Практическая работа №1. Командная строка

Источник: «Конфигурационное управление. Практическое занятие №1. Командная строка.pdf».

## Цель

Десять заданий по работе с файлами, каталогами и текстом в командной строке Linux. Скрипты написаны на Bash с использованием обычных утилит GNU.

## Запуск

В Linux откройте терминал в каталоге `practice-01`. Файлы можно запускать как `bash 01-users.sh`, поэтому предварительная смена прав не обязательна. Для проверки всего набора выполните `bash tests/run.sh`.

| № | Программа | Пример запуска | Результат |
|---|---|---|---|
| 1 | `01-users.sh` | `bash 01-users.sh /etc/passwd` | Имена пользователей по алфавиту |
| 2 | `02-protocols.sh` | `bash 02-protocols.sh /etc/protocols` | Пять записей с наибольшими номерами |
| 3 | `03-banner.sh` | `bash 03-banner.sh 'Hello from RTU MIREA!'` | Рамка по длине текста |
| 4 | `04-identifiers.sh` | `bash 04-identifiers.sh hello.c` | Уникальные слова, подходящие под синтаксис идентификатора |
| 5 | `05-register.sh` | `sudo bash 05-register.sh ./03-banner.sh` | Копия с правами `0755` в `/usr/local/bin` |
| 6 | `06-check-comments.sh` | `bash 06-check-comments.sh ./src` | Файлы `.c`, `.js`, `.py` без комментария в первой строке |
| 7 | `07-duplicates.sh` | `bash 07-duplicates.sh ./data` | Группы файлов с одинаковым содержимым, включая подкаталоги |
| 8 | `08-archive-by-extension.sh` | `bash 08-archive-by-extension.sh txt result.tar` | Архив файлов `.txt` из текущего каталога |
| 9 | `09-spaces-to-tabs.sh` | `bash 09-spaces-to-tabs.sh input.txt output.txt` | Каждая четвёрка пробелов заменена табуляцией |
| 10 | `10-empty-text-files.sh` | `bash 10-empty-text-files.sh ./data` | Пустые файлы с текстовыми расширениями в указанном каталоге |

Все скрипты сообщают об ошибочном вызове или недоступных входных файлах через stderr и ненулевой код завершения. Скрипт №5 поддерживает второй аргумент для установки в тестовый каталог вместо системного.

## Результаты и пояснения

1. Содержимое первого поля `/etc/passwd` отделяется `cut`, затем сортируется через `sort` в локали `C`. В тесте строки `bob` и `alice` дали `alice`, `bob`.
2. В `/etc/protocols` второе поле содержит номер IP-протокола, а не TCP/UDP-порт. В задании сказано «портов», но пример относится к номерам протоколов. Скрипт сортирует второе поле. В тесте верхние номера: `150`, `140`, `139`, `138`, `137`.
3. Ширина рамки вычисляется из длины аргумента. Пример из задания даёт строку `| Hello from RTU MIREA! |` между двумя границами `+-----------------------+`. Для кириллицы терминалу нужна локаль UTF-8; текст должен быть однострочным.
4. По приведённому в задании примеру идентификаторы извлекаются регулярным выражением из **всего** текста файла. Поэтому в результат могут попасть слова из комментариев, строковых литералов и `#include`. Это соответствует ожидаемому набору для `hello.c` из задания, но не заменяет синтаксический анализатор языка.
5. `install -m 0755` выставляет права на копии и помещает её в каталог назначения. Для `/usr/local/bin` обычно требуются права администратора. Тест использует временный каталог и проверяет возможность запуска установленной копии.
6. Проверяются файлы во всём дереве каталога. Для Python допускается `#`, для C и JavaScript допускаются `//` и `/*` после пробелов. Если найден файл без комментария, код завершения равен `1`.
7. Файлы сначала группируются по SHA-256, затем каждый кандидат дополнительно сравнивается байт в байт через `cmp`. Символические ссылки не включаются; пути с пробелами обрабатываются корректно.
8. Подбираются только обычные файлы текущего каталога, без подкаталогов. Если архив с тем же именем уже существует, он не попадает внутрь самого себя. Содержимое можно проверить командой `tar -tf result.tar`.
9. Замена выполняется слева направо без изменения других символов. Восемь подряд идущих пробелов превращаются в две табуляции. Входной и выходной файл должны различаться.
10. У пустого файла нет содержимого, по которому можно определить его тип. Поэтому «текстовый» определяется по расширению: `.txt`, `.md`, `.csv`, `.json`, `.xml`, `.yaml`, `.yml`, `.ini`, `.log`, `.py`, `.js`, `.c`, `.h`, `.sh` (регистр не важен). Поиск ограничен указанным каталогом без подкаталогов.

## Проверка

`bash tests/run.sh` выполняет 11 проверок для десяти программ и выводит `Успешно: 11 проверок`. Этот результат получен и в Git Bash на Windows, и в Ubuntu 24.04 (WSL). ShellCheck 0.9.0 проверил все десять решений и тестовый скрипт без предупреждений.

Дополнительно скрипты №1 и №2 запущены в Ubuntu с настоящими системными файлами. Первый вывел имена учётных записей по алфавиту; второй вывел пять верхних записей: `262 mptcp`, `143 ethernet`, `142 rohc`, `141 wesp`, `140 shim6`. Эти данные относятся к данной установке Ubuntu и могут отличаться в другой системе.

В Git Bash на Windows команды запускаются так же, но системные файлы `/etc/passwd` и `/etc/protocols` содержат другие данные. Установку в `/usr/local/bin` удобнее показывать в Linux или WSL. PowerShell не запускает эти `.sh` файлы напрямую; нужен Bash.
