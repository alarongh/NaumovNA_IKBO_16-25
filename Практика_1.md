## Задача 1

**Условие.** Вывести имена пользователей из файла `passwd` в алфавитном порядке.

Файл: [01-users.sh](practice-01/01-users.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

passwd_file=${1:-/etc/passwd}
if [[ ! -f $passwd_file || ! -r $passwd_file ]]; then
  printf 'Не удаётся прочитать файл: %s\n' "$passwd_file" >&2
  exit 1
fi

cut -d: -f1 -- "$passwd_file" | LC_ALL=C sort
```

## Задача 2

**Условие.** Вывести пять записей `/etc/protocols` с наибольшими числовыми значениями, сначала номер, затем название.

В задании использовано слово «портов». В этом файле записаны номера IP-протоколов, а не TCP/UDP-порты. Решение следует структуре файла и примеру из задания.

Файл: [02-protocols.sh](practice-01/02-protocols.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

protocols_file=${1:-/etc/protocols}
if [[ ! -f $protocols_file || ! -r $protocols_file ]]; then
  printf 'Не удаётся прочитать файл: %s\n' "$protocols_file" >&2
  exit 1
fi

# В /etc/protocols второе поле - номер протокола, а не сетевой порт.
awk '
  /^[[:space:]]*#/ || /^[[:space:]]*$/ { next }
  $2 ~ /^[0-9]+$/ { print $2, $1 }
' "$protocols_file" | LC_ALL=C sort -k1,1nr -k2,2 | awk 'NR <= 5'
```

Запуск:

```bash
bash "$scripts/02-protocols.sh" /etc/protocols
```

Результат:

```text
262 mptcp
143 ethernet
142 rohc
141 wesp
140 shim6
```

<details>
<summary>Как работает</summary>

Первый `awk` пропускает комментарии и пустые строки, затем переставляет два поля: номер перед названием. `sort -k1,1nr` сортирует первое поле как число по убыванию. `-k2,2` сортирует одинаковые номера по названию. Последний `awk` оставляет первые пять строк.

</details>

## Задача 3

**Условие.** Написать программу `banner` на Bash, которая выводит текст в рамке. Ширина рамки должна зависеть от длины текста. Проверить код в ShellCheck.

Файл: [03-banner.sh](practice-01/03-banner.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

if (( $# != 1 )); then
  printf 'Использование: %s ТЕКСТ\n' "$0" >&2
  exit 2
fi

text=$1
# Ширина измеряется в символах; для кириллицы нужна UTF-8 локаль.
width=${#text}
printf -v border '%*s' "$((width + 2))" ''
border=${border// /-}
printf '+%s+\n| %s |\n+%s+\n' "$border" "$text" "$border"
```

Запуск:

```bash
bash "$scripts/03-banner.sh" 'Hello from RTU MIREA!'
bash "$scripts/03-banner.sh" OK
```

Результат:

```text
+-----------------------+
| Hello from RTU MIREA! |
+-----------------------+
+----+
| OK |
+----+
```

<details>
<summary>Как работает</summary>

`$1` содержит переданный текст, `${#text}` вычисляет его длину. К ширине добавляются два места для пробелов по краям. `printf -v` записывает строку пробелов в переменную `border`, затем `${border// /-}` заменяет их дефисами. Последний `printf` печатает верхнюю границу, текст и нижнюю границу. Для кириллицы нужна локаль UTF-8. Пример рассчитан на одну строку без управляющих символов.

</details>

## Задача 4

**Условие.** Вывести без повторений идентификаторы из исходного файла по правилам C/C++ или Java.

Файл: [04-identifiers.sh](practice-01/04-identifiers.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

if (( $# != 1 )) || [[ ! -f $1 || ! -r $1 ]]; then
  printf 'Использование: %s ИСХОДНЫЙ_ФАЙЛ\n' "$0" >&2
  exit 2
fi

# По образцу задания ищем слова во всём тексте, включая комментарии и строки.
if ! grep -Eq '[[:alpha:]_][[:alnum:]_]*' -- "$1"; then
  printf '\n'
  exit 0
fi
grep -Eo '[[:alpha:]_][[:alnum:]_]*' -- "$1" | LC_ALL=C sort -u | paste -sd ' ' -
```

Входной файл `hello.c`:

```c
#include <stdio.h>

int main(void)
{
    printf("hello, world\n");
    return 0;
}
```

Создание входного файла и запуск:

```bash
printf '#include <stdio.h>\nint main(void) { printf("hello, world\\n"); return 0; }\n' > hello.c
bash "$scripts/04-identifiers.sh" hello.c
```

Результат:

```text
h hello include int main n printf return stdio void world
```

<details>
<summary>Как работает</summary>

Регулярное выражение ищет последовательность, которая начинается с буквы или `_` и продолжается буквами, цифрами или `_`. Ключ `-o` у `grep` выводит совпадения отдельно. `sort -u` сортирует и убирает повторы, `paste` соединяет строки пробелами. По примеру задания поиск идёт по всему тексту: слова из `#include`, строк и комментариев тоже попадают в результат. Это поиск по шаблону, а не полноценный разбор программы.

</details>

## Задача 5

**Условие.** Зарегистрировать пользовательскую команду: выставить права доступа и скопировать программу в `/usr/local/bin`.

Файл: [05-register.sh](practice-01/05-register.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

if (( $# < 1 || $# > 2 )); then
  printf 'Использование: %s ПРОГРАММА [КАТАЛОГ_НАЗНАЧЕНИЯ]\n' "$0" >&2
  exit 2
fi

source_file=$1
destination=${2:-/usr/local/bin}
if [[ ! -f $source_file || ! -r $source_file ]]; then
  printf 'Не удаётся прочитать программу: %s\n' "$source_file" >&2
  exit 1
fi
if [[ ! -d $destination ]]; then
  printf 'Каталог назначения не существует: %s\n' "$destination" >&2
  exit 1
fi

install -m 0755 -- "$source_file" "$destination/$(basename -- "$source_file")"
printf 'Установлено: %s/%s\n' "$destination" "$(basename -- "$source_file")"
```

Команда установки в каталог из задания:

```bash
sudo bash "$scripts/05-register.sh" "$scripts/03-banner.sh"
```

Этот вызов устанавливает копию в `/usr/local/bin/03-banner.sh`. Обычно здесь нужны права администратора. Если `/usr/local/bin` входит в `PATH`, после установки команду можно вызвать как `03-banner.sh 'Привет'` из любого каталога.

Проверка в отдельном каталоге без изменения системных файлов:

```bash
mkdir bin
bash "$scripts/05-register.sh" "$scripts/03-banner.sh" ./bin
stat -c '%a %n' ./bin/03-banner.sh
./bin/03-banner.sh OK
```

Полученный результат проверки:

```text
Установлено: ./bin/03-banner.sh
755 ./bin/03-banner.sh
+----+
| OK |
+----+
```

<details>
<summary>Как работает</summary>

Без второго аргумента выбирается `/usr/local/bin`. `basename` оставляет имя файла без пути. `install -m 0755` копирует файл и назначает права: владельцу чтение, запись и запуск, остальным чтение и запуск. Исходный скрипт остаётся на месте. Второй аргумент нужен для проверки в обычном каталоге.

</details>

## Задача 6

**Условие.** Проверить наличие комментария в первой строке файлов с расширениями `.c`, `.js` и `.py`.

Файл: [06-check-comments.sh](practice-01/06-check-comments.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

root=${1:-.}
if [[ ! -d $root ]]; then
  printf 'Каталог не существует: %s\n' "$root" >&2
  exit 1
fi

failed=0
checked=0
while IFS= read -r -d '' file; do
  ((checked += 1))
  first_line=''
  IFS= read -r first_line < "$file" || true
  first_line=${first_line#$'\xef\xbb\xbf'}
  case $file in
    *.py) pattern='^[[:space:]]*#' ;;
    *.c|*.js) pattern='^[[:space:]]*(//|/\*)' ;;
  esac
  if [[ ! $first_line =~ $pattern ]]; then
    printf 'Нет комментария в первой строке: %s\n' "$file"
    ((failed += 1))
  fi
done < <(find "$root" -type f \( -name '*.c' -o -name '*.js' -o -name '*.py' \) -print0)

printf 'Проверено: %d; без комментария: %d\n' "$checked" "$failed"
(( failed == 0 ))
```

Создание примеров и запуск:

```bash
mkdir comments
printf '# comment\nprint(1)\n' > comments/good.py
printf '// comment\nconst x = 1;\n' > comments/good.js
printf '/* comment */\nint x;\n' > comments/good.c
printf 'print(2)\n' > comments/bad.py
bash "$scripts/06-check-comments.sh" ./comments
printf 'Код завершения: %d\n' "$?"
```

Результат:

```text
Нет комментария в первой строке: ./comments/bad.py
Проверено: 4; без комментария: 1
Код завершения: 1
```

<details>
<summary>Как работает</summary>

`find` находит файлы нужных расширений, включая подкаталоги. `read` читает первую строку каждого файла. `case` выбирает начало комментария: `#` для Python, `//` или `/*` для C и JavaScript. Шаблон допускает пробелы перед комментарием. Если хотя бы один файл не прошёл проверку, скрипт завершается с кодом `1`. Это результат проверки, а не ошибка запуска.

</details>

## Задача 7

**Условие.** Найти файлы с одинаковым содержимым в указанном каталоге и его подкаталогах.

Файл: [07-duplicates.sh](practice-01/07-duplicates.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

root=${1:-.}
if [[ ! -d $root ]]; then
  printf 'Каталог не существует: %s\n' "$root" >&2
  exit 1
fi

declare -A buckets=()
declare -a representatives=() members=() counts=()

while IFS= read -r -d '' file; do
  digest=$(sha256sum -- "$file")
  digest=${digest:0:64}
  match=-1
  for index in ${buckets[$digest]-}; do
    if cmp -s -- "$file" "${representatives[index]}"; then
      match=$index
      break
    fi
  done

  printf -v quoted '%q' "$file"
  if (( match >= 0 )); then
    members[match]+=$'\n'"$quoted"
    ((counts[match] += 1))
  else
    index=${#representatives[@]}
    representatives+=("$file")
    members+=("$quoted")
    counts+=(1)
    buckets[$digest]="${buckets[$digest]-} $index"
  fi
done < <(find "$root" -type f -print0 | LC_ALL=C sort -z)

found=0
for ((index = 0; index < ${#representatives[@]}; index++)); do
  if (( counts[index] > 1 )); then
    ((found += 1))
    printf 'Группа %d (%d копии):\n%s\n' "$found" "${counts[index]}" "${members[index]}"
  fi
done
printf 'Групп дубликатов: %d\n' "$found"
```

Создание примеров и запуск:

```bash
mkdir -p data/nested
printf 'same\n' > data/a.txt
printf 'same\n' > data/nested/b.txt
printf 'other\n' > data/c.txt
bash "$scripts/07-duplicates.sh" ./data
```

Результат:

```text
Группа 1 (2 копии):
./data/a.txt
./data/nested/b.txt
Групп дубликатов: 1
```

<details>
<summary>Как работает</summary>

Имя файла не определяет, является ли он дубликатом. Скрипт вычисляет SHA-256 содержимого и собирает файлы с одинаковой контрольной суммой в кандидаты на одну группу. Затем `cmp -s` сравнивает их содержимое байт в байт. Массивы хранят представителя группы, список путей и количество файлов. Выводятся только группы, где найдено больше одного файла. Символические ссылки не включаются.

</details>

## Задача 8

**Условие.** Найти в текущем каталоге файлы с расширением из аргумента и собрать их в архив `tar`.

Файл: [08-archive-by-extension.sh](practice-01/08-archive-by-extension.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

if (( $# < 1 || $# > 2 )); then
  printf 'Использование: %s РАСШИРЕНИЕ [АРХИВ.tar]\n' "$0" >&2
  exit 2
fi

extension=${1#.}
if [[ ! $extension =~ ^[[:alnum:]_+-]+$ ]]; then
  printf 'Некорректное расширение: %s\n' "$1" >&2
  exit 2
fi
archive=${2:-"files-${extension}.tar"}

files=()
while IFS= read -r -d '' file; do
  if [[ -e $archive && $file -ef $archive ]]; then
    continue
  fi
  files+=("$file")
done < <(find . -maxdepth 1 -type f -name "*.${extension}" -print0 | LC_ALL=C sort -z)

if (( ${#files[@]} == 0 )); then
  printf 'В текущем каталоге нет файлов .%s\n' "$extension" >&2
  exit 1
fi

tar -cf "$archive" -- "${files[@]}"
printf 'Архив %s: %d файлов\n' "$archive" "${#files[@]}"
```

Создание примеров и запуск:

```bash
mkdir archive
printf 'A\n' > archive/a.txt
printf 'B\n' > archive/b.txt
printf 'C\n' > archive/c.md
cd archive
bash "$scripts/08-archive-by-extension.sh" txt result.tar
tar -tf result.tar
cd ..
```

Результат:

```text
Архив result.tar: 2 файлов
./a.txt
./b.txt
```

<details>
<summary>Как работает</summary>

`find` выбирает обычные файлы с нужным расширением. `-maxdepth 1` исключает поиск внутри подкаталогов. Пути записываются в массив `files`, затем передаются в `tar`. У `tar -cf` ключ `c` создаёт архив, `f` задаёт его имя. Команда `tar -tf` показывает содержимое, не распаковывая архив. Файл `c.md` не попал в архив, так как его расширение отличается.

</details>

## Задача 9

**Условие.** Заменить последовательности из четырёх пробелов символом табуляции. Входной и выходной файлы передаются аргументами.

Файл: [09-spaces-to-tabs.sh](practice-01/09-spaces-to-tabs.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

if (( $# != 2 )); then
  printf 'Использование: %s ВХОДНОЙ_ФАЙЛ ВЫХОДНОЙ_ФАЙЛ\n' "$0" >&2
  exit 2
fi
if [[ ! -f $1 || ! -r $1 ]]; then
  printf 'Не удаётся прочитать файл: %s\n' "$1" >&2
  exit 1
fi
if [[ $1 == "$2" || ( -e $2 && $1 -ef $2 ) ]]; then
  printf 'Входной и выходной файлы должны различаться\n' >&2
  exit 2
fi

sed $'s/    /\t/g' -- "$1" > "$2"
```

Создание примера и запуск:

```bash
printf 'a    b        c\n' > input.txt
bash "$scripts/09-spaces-to-tabs.sh" input.txt output.txt
cat -T output.txt
```

Результат:

```text
a^Ib^I^Ic
```

<details>
<summary>Как работает</summary>

`sed` выполняет замену четырёх пробелов табуляцией. `g` означает, что замена выполняется для всех подходящих участков строки, а не только для первого. После `a` было четыре пробела, после `b` восемь, поэтому получилась одна и две табуляции. `cat -T` показывает каждую табуляцию как `^I`; в самом файле находятся символы табуляции, а не эти два печатных знака. Входной и выходной файлы должны различаться, чтобы исходные данные не были затёрты.

</details>

## Задача 10

**Условие.** Вывести названия пустых текстовых файлов из каталога, переданного параметром.

Файл: [10-empty-text-files.sh](practice-01/10-empty-text-files.sh).

```bash
#!/usr/bin/env bash
set -euo pipefail

root=${1:-.}
if [[ ! -d $root ]]; then
  printf 'Каталог не существует: %s\n' "$root" >&2
  exit 1
fi

# Содержимое нулевой длины нельзя распознать как текст или бинарные данные.
# Поэтому текстовыми считаются файлы с перечисленными текстовыми расширениями.
find "$root" -maxdepth 1 -type f -empty \( \
  -iname '*.txt' -o -iname '*.md' -o -iname '*.csv' -o \
  -iname '*.json' -o -iname '*.xml' -o -iname '*.yaml' -o \
  -iname '*.yml' -o -iname '*.ini' -o -iname '*.log' -o \
  -iname '*.py' -o -iname '*.js' -o -iname '*.c' -o \
  -iname '*.h' -o -iname '*.sh' \
\) -print | LC_ALL=C sort
```

Создание примеров и запуск:

```bash
mkdir empty
: > empty/one.txt
: > empty/two.md
: > empty/three.bin
printf 'content\n' > empty/four.txt
bash "$scripts/10-empty-text-files.sh" ./empty
```

Результат:

```text
./empty/one.txt
./empty/two.md
```

<details>
<summary>Как работает</summary>

`-empty` выбирает файлы нулевого размера. У пустого файла нет содержимого для определения типа, поэтому в решении текстовый файл определяется по расширению. `-iname` сравнивает имя без учёта регистра. `three.bin` не подходит по расширению, а `four.txt` не пустой. Поиск ограничен самим указанным каталогом, без подкаталогов. В выводе перед именем оставлен путь к каталогу.

## Сравнение Windows и Linux

| Среда | Запуск `.sh` | Особенности |
|---|---|---|
| Ubuntu в WSL | `bash имя_файла.sh` | Есть Linux-файлы `/etc/passwd` и `/etc/protocols`; установка в `/usr/local/bin` обычно требует `sudo` |
| Git Bash в Windows | `bash имя_файла.sh` | Большинство использованных команд работают так же, но системные файлы и учётные записи отличаются |
| PowerShell в Windows | Нужен отдельный Bash, например через WSL | Синтаксис Bash не выполняется напрямую; запуск без WSL или Git Bash не подходит для этих скриптов |

В Ubuntu команда `pwd` показывает Linux-путь. В WSL диск Windows `C:` доступен по пути `/mnt/c`. Например, папка `C:\Study\NaumovNA_IKBO_16-25` в Windows доступна как `/mnt/c/Study/NaumovNA_IKBO_16-25` в WSL.
