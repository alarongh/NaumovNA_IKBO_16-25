## Этап 1. JSON и промежуточное представление

Язык программы представляет собой массив объектов с полями `op` и `b`.
Операции `load`, `read`, `store`, `popcnt` соответствуют кодам
1, 110, 12 и 54. Поле `b` является целым неотрицательным числом.
Для load допустимы 27 бит, для остальных команд 17 бит.

Пример одной команды.

```json
[{"op": "load", "b": 559}]
```

Python 3.10 или новее запускается из каталога практики.
Сборка и сторонние пакеты Python не требуются.

```powershell
New-Item -ItemType Directory -Force output
.\run.bat assemble --source examples/spec.json --output output/spec.bin --test
python -B -m unittest discover -s tests -v
```

В версии этапа 1 тестовый режим выводит поля A и B.
Тесты из сборника записаны в examples/spec.json.

| Команда | A | Биты B | Действие |
| --- | --- | --- | --- |
| load | 1 | 7-33 | Поместить B в аккумулятор |
| read | 110 | 7-23 | Прочитать слово по адресу B в аккумулятор |
| store | 12 | 7-23 | Записать аккумулятор по адресу B |
| popcnt | 54 | 7-23 | Сосчитать единицы слова по B и записать по адресу из аккумулятора |

В каждой команде поле A занимает биты 0-6.

## Этап 2. Машинный код

Код команды хранится в младших 7 битах. Операнд сдвигается на 7 бит
влево. Полученное число записывается в little-endian.
load занимает 5 байт, остальные команды занимают 3 байта.
Резервные старшие биты равны нулю.

В тестовом режиме выводятся четыре байтовые строки из спецификации.
Число команд для examples/spec.json равно 4.

```text
0x81, 0x17, 0x01, 0x00, 0x00
0xEE, 0x1A, 0x01
0x8C, 0xD9, 0x00
0x36, 0xD7, 0x01
```

spec.json проверяет кодировку четырёх независимых команд. Для исполнения
с подготовкой данных используются copy.json, popcnt.json и vector-*.json.

## Этап 3. Интерпретатор

Общая память содержит 131072 байта. Программа загружается с адреса 0.
Данные являются беззнаковыми 32-битными словами little-endian.
Адрес обозначает первый байт слова, выравнивание по 4 не требуется.
Такая модель выбрана, поскольку размер слова в задании не указан.
Запись в область кода меняет последующие инструкции.
Исполнение заканчивается на границе исходного бинарного файла.
Диапазон дампа включает обе границы, шаг равен 4 байтам.
За последним полным словом чтение и запись вызывают ошибку.

С этапа 3 CLI имеет подкоманды assemble и run.

```powershell
.\run.bat assemble --source examples/copy.json --output output/copy.bin
.\run.bat run --binary output/copy.bin --dump output/copy.xml --start 2048 --end 2056
```

В дампе по адресам 2048, 2052 и 2056 получаются 7, 11 и 19.
Исходный массив находится по адресам 1024, 1028 и 1032.


## Этап 4. popcnt

popcnt читает слово по адресу B, считает единичные биты и пишет результат
по адресу из аккумулятора. Значение аккумулятора сохраняется.
Пример popcnt.json записывает 45 в 1024, затем получает 4 по адресу 2048.

```powershell
.\run.bat assemble --source examples/popcnt.json --output output/popcnt.bin
.\run.bat run --binary output/popcnt.bin --dump output/popcnt.xml --start 2048 --end 2048
```


## Этап 5. Вектор длины 6

Каждый пример сначала записывает исходные числа в память, затем для
каждого адреса выполняет load с этим адресом и popcnt с тем же адресом.
Результаты заменяют слова исходного вектора, начиная с адреса 1024.

| Программа | Исходные числа | Результат |
| --- | --- | --- |
| vector-1.json | 0, 1, 3, 7, 15, 31 | 0, 1, 2, 3, 4, 5 |
| vector-2.json | 42, 85, 255, 256, 1023, 65535 | 3, 4, 8, 1, 10, 16 |
| vector-3.json | 134217727, 67108864, 123456, 559, 942, 435 | 27, 1, 6, 6, 7, 6 |

Полная демонстрация запускается из PowerShell.

```powershell
pwsh -NoProfile -File examples/demo.ps1
```

XML содержит элементы cell с атрибутом address и десятичным значением.
Шесть адресов векторного дампа равны 1024, 1028, 1032, 1036, 1040, 1044.
Двоичные файлы и дампы создаются в output, исключённом из Git.

## Файлы программы и ошибки

На Windows с Python 3.14.7 прошли 17 тестов и сценарий examples/demo.ps1.
Все четыре эталонные команды совпали с байтами из задания.
Проверены XML-результаты копирования, отдельной popcnt и трёх векторов.

format.py разбирает JSON и ограничения полей. codec.py кодирует команды
и декодирует байты. machine.py исполняет операции в общей памяти.
dump.py формирует XML. files.py проверяет совпадение путей и записывает
выходной файл через временный. cli.py обрабатывает параметры и ошибки.

Неправильный JSON, повторные ключи, неизвестная операция, отрицательный
операнд и превышение разрядности приводят к сообщению и коду 1.
Декодер проверяет код операции, длину и резервные биты. Диапазон дампа
должен состоять из полных слов в пределах памяти. Ошибки параметров
argparse завершают запуск с кодом 2.
